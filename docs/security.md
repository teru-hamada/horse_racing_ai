# セキュリティ運用

## 自動処理の権限

- 日次の依存ライブラリ導入・外部データ取得・予想処理は `contents: read` で実行する。
- 非公開側からは読み取り専用Deploy keyで指定コミットを取得する。認証情報はGitに保持しない。
- 公開ファイルの登録は別のVMで行う。DB・モデル・秘密鍵・予想処理のPython環境を渡さない。
- 公開登録ジョブは取得したArtifact内のコードを実行しない。チェックアウトしたコードで検査する。
- 予想開始後に公開済みデータが更新された場合は上書きせず、再実行を要求する。
- Pages配信権限は配信ジョブだけに与える。

## 公開前の検査

`scripts/validate_public_site.py` は、許可した拡張子・安全なパス・テキスト内容を検査する。
監査ZIPは展開せず、中のファイル形式・サイズ・秘密情報・パスを検査する。
モデル・DB・秘密鍵、symlink、ZIP内の不正パス、暗号化ZIPは拒否する。
公開HTMLのスクリプトはジョブ状況ページの既知のファイルだけを許可し、
インラインスクリプト・イベントハンドラー・iframe・危険なURLは拒否する。
JavaScript本体もチェックアウトした既知のソースと一致する場合だけ許可する。

```powershell
.venv/Scripts/python.exe scripts/validate_public_site.py docs --check-repository
```

`--check-repository` はGit追跡対象へのDB・モデル・代表的な認証情報の再混入も検査する。
検出はすべての種類の機密情報を保証するものではないため、公開内容の判断も必要。

## 継続的な検査と更新

`Security checks` ワークフローは関連コードのpush・PRと週次スケジュールで実行する。

- 公開ファイル検査と不正Artifact・古い予想の上書き防止テスト。
- CodeQLのPython解析（security-extended）。
- 非公開側の固定実行環境とGUI環境を構築し、間接依存も含めて `pip-audit` で検査。

監査用スクリプトはCPU版PyTorchの `+cpu` 接尾辞を上流バージョンへ対応付ける。
PyPIにCPU版がないことを理由にPyTorchの検査を省略せず、未検査パッケージがあれば失敗させる。

PRで実行するコードには非公開リポジトリの鍵を渡さない。
依存関係監査はデフォルトブランチのpush・週次・手動実行だけで行う。
DependabotはGitHub ActionsとPython依存の更新PRを作成する。自動マージはしない。
すべての外部Actionsは公式リポジトリで確認した完全なコミットSHAへ固定する。

`requirements-security.txt` は修正版の最低バージョンを定義する。
モデル保存形式に関わるライブラリの固定版は非公開バンドルが管理し、勝手に更新しない。
モデル関連パッケージの更新が必要な場合は、互換性と再現性を検証してバンドルを再生成する。

## GitHub側の設定

- Actionsの標準トークン権限は読み取り専用、PRレビューの承認は禁止。
- 公開側はmainの強制push・削除を禁止し、直線的な履歴を要求する。
- 日次処理が公開ファイルを登録するため、mainへの全pushにPR承認を要求する設定にはしない。
  CODEOWNERSはPRのレビュー依頼先を示す。単独で直接pushを禁止するものではない。
- 両リポジトリの書き込み権限は所有者だけに限定する。
- 両リポジトリでDependabot alertsとセキュリティ更新を有効にする。
- 公開側のSecret scanning・Push protectionとPagesのHTTPSを有効にする。
- 保管専用の非公開側ではActionsを無効にする。公開側からのcheckoutには影響しない。

GitHub Freeの非公開リポジトリではブランチ保護を利用できない。
非公開側の追加機能は有料化せず、利用可能な保護と公開側のコミットSHA固定で運用する。
アカウントの2要素認証・パスキーは所有者自身で設定する。
Deploy keyの権限・Actions Secrets・書き込み権限を持つ利用者は定期的に確認する。
